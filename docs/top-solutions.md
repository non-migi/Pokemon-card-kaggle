## 1位 Luca(yijieyuan) — 最終Elo 1398.2 / 1291.1

タイトル "Aim to Be a Pokémon Master"。**自己対戦による強化学習を、我々の1万倍以上の
計算規模で回していた**。模倣学習は使っていない(少なくとも主役ではない)。

先手勝率51.3〜52.5% / 後手47.4〜48.6% と、先手有利もこの規模で測っている。

ステージ設計は「**広いデッキ分布 → 徐々に狭く専門化**」。Stage 2以降は
Dragapult ex と Hydrapple ex 中心の小さいプールへ絞り、Stage 4は
**1デッキ固定 × 凍結した過去世代のラダー**。勝率EMAが低い相手を多くサンプルする。

### デッキ開発(ここが我々と決定的に違う)
- **646デッキを台帳管理**(537 active / 109 dormant)、**38アーキタイプ / 260 active family**
- デッキを**静的カード特徴 + 学習した埋め込みで階層クラスタリング**し、
  ポケモン枠やエネルギー枠の構成が変わる枝で分割
- **常時稼働のローカルアリーナ**(アーキタイプごとに1枠)でチェックポイント×デッキを評価
- アーキタイプ内総当たり → 上位10デッキ同士の**クロス対戦を1ペア512戦**
- **4枚未満の差の変種**を作って弱点対面を潰す。結果 f38fb5 は対a2(Mega Kangaskhan)
  **95.7%**、f04db8 は対Alakazam 43.4%
- Stage 3/4 直前のアリーナ首位は Hydrapple(a7)平均 **76.3%**、Dragapult(a3)**73.0%**、
  どちらも45%未満の対面が1つだけ。Hydrapple が Dragapult と互角かつ a3 の弱点 a2 を
  見られるので両方を最終候補にした

## 24位 ymgaq「Boss's Orders Are All You Need」— 人口ベースRL生態系

小さいTransformerを中心に、**模倣学習 → 蒸留 → PPO** のパイプラインを回し、
多数の小型モデルを同時に育てて共通環境で強さと対面を測り続ける。
- **ベイズレーティング**と**動的な対戦相手配分**
- **勝率プロファイルでクラスタリング**して総合力と対面別の穴を見る
- 推論はC++、模倣はGBDT、それをTransformerへ蒸留
- デッキ開発は専門知識と評価結果の組み合わせ
- 実装サンプルを公開: https://github.com/ymgaq/ptcg-population-rl

出典: https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/writeups/24th-solution-a-population-based-rl-ecosystem

## 我々との差はどこにあったか

| | 1位 | 我々 |
|---|---|---|
| 学習則 | 自己対戦RL(PPO) | 模倣学習(BC)のみ |
| 学習量 | 3.6億対局 / 590億サンプル | 347万判断(公式リプレイ) |
| 天井 | 自己対戦なので上限なし | **模倣元の平均 ≈ レート1050** |
| 相手モデル | 履歴から推定してモデル入力へ | 探索時は決定的argmax(→探索が−88点) |
| デッキ選択 | 646デッキ台帳 + 常時アリーナ + 512戦/ペア | 公式Daily Topの最頻60枚を採用 |
| デッキ調整 | 4枚未満の変種で弱点を潰す | 一切いじらない(再学習コストのため) |

**我々の08-16時点の自己診断(「BCの天井が約1050、金は1131なので路線では届かない」)は
正しかった**ことが裏付けられた。1位は最初からその天井の外側、つまり自己対戦にいた。
我々がExpert Iteration(蒸留判断5.9万件で停止)を続けていれば、方向としては24位解法の
パイプラインに合流していた。

**2番目に効いていた差はデッキ探索の規模**。我々は「勝者の最頻60枚をそのまま使う」で止めたが、
1位は646デッキを常時回して対面表を作り、カード1〜3枚差の変種まで検証していた。
これは自己対戦ほどの計算資源を必要としない領域で、次に同種のコンペに出るなら
**ここが最も費用対効果の高い投資先**になる。

**環境側(シミュレータ)も同程度に重い**: 固有で約 **8.7億対局**。
1試合30msなら 7,266 コア時間(64コアで4.7日)、100msなら 24,218 コア時間(64コアで16日)。
⚠️ 公式エンジンをPythonからそのまま回すと観測のシリアライズで桁が変わるので、
**自前の高速シミュレータ(C++/ベクトル化)がほぼ必須**。ここが金銭より重い参入障壁。

**クラウド費用の目安**: GPU 1,500〜2,500 USD + CPU 数百 USD、8GPUで実時間 1〜2週間。
つまり「研究所規模」ではなく「本気の個人プロジェクト規模」。ただし自前エンジンの実装工数は別。

**縮小版の現実解**: Stage 4 の1デッキ特化は増分 9〜17 B サンプル(全体の6〜11%)しかない。
1デッキ専用エージェントを1体だけ育てるなら **100〜350 GPU時間**(4090で数日、50〜150 USD)で届く。
さらに、我々に最も欠けていた**デッキ探索(646デッキの常時アリーナと対面表)はGPUをほぼ使わない**。
次にやるなら投資順は ①高速シミュレータ ②デッキアリーナ ③1デッキ特化の自己対戦。
