## 1. この報告の主張

我々が学んだことの大半は、常識的な事前予想と食い違う。5つの主張を先に述べる。それぞれ本番ラダー実験か事前登録A/Bテストで裏づけられており、最終2提出は締切後それぞれ1,000戦を追跡したので、以下の数字はすべて予測ではなく測定値である。

1. **ラダーはアーキタイプで層化している(図9)。** Grimmsnarlは800〜900帯では相手の59〜64%だが、900〜1000帯では28〜33%に落ち、代わりにOgerpon・Kangaskhan・Dragapultが増える。エージェントの平衡レートは平均勝率ではなく、**1つ上の帯で誰に会うか**で決まる。
2. **模倣学習の方策は1つのデッキのための方策である。** 同じデッキが、Alakazam使いから複製した方策では751、Grimmsnarl使いから複製した方策では840だった。
3. **模倣の上に探索を載せると88点悪化した。** 同一デッキ・同一重みの本番A/B(図4)。
4. **レートは長い裾で失われ、その裾は文字どおり見えていなかった。** 相手の43枚のカードが「未知」トークンに潰れていた。直したのはモデル改良ではなく、データの日次更新だった。
5. **チームスコアは2提出のmaxなので、専門型+万能型は安全策2本に勝る。** 専門型(Ogerpon、対Grimmsnarl 89.6%)がチームスコアを取り、万能型(Grimmsnarl)が専門型の穴を埋めた。

## 2. 手法を1段落で(図6)

使うアーキタイプごとに、公式Daily Topリプレイを取得し、キーカードを4枚以上積むデッキのチームの**勝者側**の `(観測, 選んだ手)` ペアだけを残し、2タワーランカーを学習する。94特徴の状態タワーと、16次元の学習カード埋め込みを含む48特徴のオプションタワー、各128隠れユニット、内積をロジットとし、合法手上のsoftmaxを交差エントロピーで学習する。書き出したnumpy重みは150KB、1判断は1ミリ秒未満で、1試合600秒のうち中央値3秒(最大9秒)しか使わずタイムアウトはゼロ。出荷するデッキはその同じ勝者たちの最頻60枚なので、デッキと方策は一体の成果物である。レバーは容量ではなく忠実度だった。holdout top-1は70.3%→75.6%(図5)に上がり、データ日数の追加・カード語彙の拡張・エポック7以降に学習率を半減する12エポック日程が効いた一方、容量拡大(+0.2pt)、エリート限定データ(47.9% / 400)、重み平均(44.4% / 400)は反証され無効にしてある。

## 3. 5つの主張と証拠

### 3.1 レート帯の生態(主張1)

最終2,000戦を相手の最終LBレートと結合した(図9)。相手構成は帯をまたいで定常ではない。700未満は珍しいデッキとLucarioの動物園、700〜800はAlakazam偏重(43%)、800〜900はGrimmsnarlの単一栽培(59〜64%)、900〜1000はOgerpon(13〜16%)、Kangaskhan(11〜13%)、Dragapult、Alakazamに分散し、Grimmsnarlは約30%まで下がる。

これで両方の最終レートが定量的に説明できる。Ogerponエージェントは800〜900帯で70%勝ち(そこではGrimmsnarlに93%、n=258)、900〜1000帯では37%(そこでもGrimmsnarlには82%、n=101、だがKangaskhanミルに0/49、Alakazamに18%、自身のミラーで31%)。そのためレートは2週間875〜909の帯で振れ、905.8で凍結した。Grimmsnarlの供給が薄くなる、まさにその高度である。Grimmsnarlエージェントは700〜800で63%、800〜900で49%で、835付近に釘付けになる。2因子モデルで効果を分離できる(図10)。各帯の構成に、帯を区別しないエージェントのアーキタイプ別勝率を掛けるだけで(帯ごとの当てはめなし)、非単調な山が再現される。Ogerponエージェントの800〜900帯を68.6%と予測し(観測69.8%)、900〜1000帯では46.7%への落ち込みを予測する(観測36.9%)。残差は帯ごとに約−10ポイントの滑らかな相手の強さの勾配である。専門型がどこに停まるかを決めるのは、技量だけではなく構成である。**実用的な規則:** 帯Bから上がるには帯B+1の構成に勝たねばならない。したがってデッキ選択は現在の帯ではなく**次の帯**のメタゲームに対して行うべきである。

### 3.2 1デッキ1方策(主張2)

Alakazam学習の方策で操作した最初のGrimmsnarl提出は751で凍結し、Grimmsnarl学習の方策で操作したGrimmsnarlデッキは840に達した。ローカルでは、Alakazam方策で他のデッキを操作すると弱いスパーリング壁に88.9%勝つのに、同じアーキタイプの実戦では74.3%を落とした。以後に作った「壁」はすべてそのデッキの勝者で学習した(デッキ, 方策)ペアで、再学習なしにカードを1枚も変えなかった。

### 3.3 探索は害になった(主張3)

デッキと`bc_grim2`の重みを共有し、BC top-5をロールアウトで並べ替える8秒の決定化探索の有無だけが違う2提出を並走させた。210戦と158戦の後: 純BC 840.0、探索751.6(図4)。ローカル壁と符号が一致する(67.1% 対 46.0%、400戦と200戦)。機構: サンプルした世界は隠れカードだけを変え、相手モデルは決定的argmaxだったので各世界は終局までの一本道になり、価値関数なしの140手ロールアウトが方策誤差を複利で積む。確率的ロールアウトは悪化させ(温度0.5 / 1.0 → 50.0% / 34.3%)、AUC 0.851の価値網もA/Bに負けた(47.8% / 400)。純粋な模倣を出荷し、「探索は効く」は本物の相手モデルを持ってから改めて獲得すべき主張として扱っている。

### 3.4 見えない裾(主張4)

210戦時点でGrimmsnarlエージェントは主戦場で勝っていた(ミラー55.7%、Alakazam 58.5%)のに総合50%だった。十数種の珍しいデッキとの26戦が3勝23敗だったからである。原因は機械的だった。143枚の語彙が相手の43枚(うち41枚がポケモン)を索引0に写していたため、方策はそれらを区別できなかった。20日分のリプレイで作り直す(語彙211)と珍しいデッキのバケットは65%に上がった(図2右)。したがってデータ更新は正しさの要件である。**止めると新しいデッキが見えなくなる。**

### 3.5 max-of-twoの下でのポートフォリオ(主張5)

最終ペアは意図的に逆相関にした(図2)。Ogerpon専門型は対Grimmsnarl 89.6%(n=394)、Garchomp 76%、珍しいデッキ59%だが、Alakazam 30%、Lopunny 12%、Kangaskhan 9%。Grimmsnarl万能型はAlakazam 60%、Archaludon 72%、Dragapult 67%、珍しいデッキ65%、ミラー51%で、唯一の穴がOgerpon(12%)。互いの最悪対面を補い、max演算子によって振れの大きい専門型がスコアを運び、万能型が下限を抑える。同一ビルドを600から再提出すると同じ近傍に収束した(905.8 / 902.8 と 843.6 / 834.6)ので、この分担は再現可能である。

プロセスが間違えた1つの判断も開示する。事前登録した「チェックポイントで650未満なら差し替え」規則が、OgerponエージェントがGrimmsnarlの相手に**ゼロ回**しか会っていない31戦の標本で発動した。人間がそれを覆し、そのビルドは905.8で終えた。帯の生態の下では、専門型の序盤の試合はその平衡プールの標本ではない。

### 3.6 うまくいかなかったこと(簡潔に)

明示的な一撃死ガード(Lopunny/Ogerponに対する13敗中12敗で見つかった、計算可能なKO圏への昇格/進化を拒否)は無害としてのみ生き残った。同じパターンは勝ち試合でも同率で起き、効果は判定不能(Δ +0.25 / −1.50 / −4.25pt)だった。さらに2つの手書きルールは反証された(−4.0pt)。残る弱点はKangaskhanミル(43敗中23敗が自山切れ)で、模倣元の勝者がこの対面をほとんど経験していないため、方策はドローの節約を学んでいない。

## 4. デッキコンセプト(図8、CSV添付)

**デッキA — Teal Mask Ogerpon ex(最終1枠目、905.8)。** Ogerponを4枚採用した勝者86チームの最頻60枚。Ogerpon ex 4、基本草エネルギー18、Grow Grass Energy 2、Bug Catching Set ×4、Energy Search ×4、Energy Retrieval ×2、Judge ×4、Lillie's Determination ×4、Boss's Orders ×3、Lively Stadium ×2。Ogerponの特性は毎ターン手札から草エネルギーを付けて1枚引き、Myriad Leaf Showerは**両方の**バトルポケモンに付いたエネルギー1枚につき30を加算する。だから全てのトレーナーズはエネルギーを探すか回収するか、加速しながら相手の手札を妨害する。対面の論理は構造的である。Grimmsnarl exのPunk Upは悪エネルギーを最大5枚一気に置くが、相手バトルポケモンのエネルギー1枚ごとに我々の攻撃が30増えるので、210HPのたねポケモンはStage 2デッキを強くしている加速そのものを罰する。それが89.6%である。「4枚以上」フィルタは不可欠だった。素朴な「Ogerponを含む」検索はOgerponを1枚差ししたKangaskhan/Crustleミルリストを拾い、ミルの方策を学習していたはずである。

**デッキB — Marnie's Grimmsnarl ex / Froslass(最終2枠目、834.6)。** 7月23日のTop-8 Grimmsnarlチームの合意リスト(Grimmsnarl使用111チーム中82チームが同一の60枚)。Impidimp/Morgrem/Grimmsnarl ex 4-3-3、Munkidori 4、Snorunt/Froslass 2-2、Spikemuth Gym ×4、Rare Candy ×3、Buddy-Buddy Poffin ×4、Poké Pad ×4、Petrel ×4。Rare CandyからPunk Upでエネルギー5枚、FroslassのFreezing ShroudでダメカンをばらまきMunkidoriで移し、320HPの体からShadow Bullet(180+ベンチ30)。より速いエネルギー加算型アタッカー以外に悪い対面がなく、平坦なプロファイルになる。

**選択規則。** 我々に欠けているカードの直感ではなく、(a)次に勝たねばならない帯での勝者チームシェア(図7、9)、(b)その正確なリストに対するクリーンな勝者データの量、(c)自陣最強エージェントに対する壁の結果。Ogerpon方策は提出の5日前に、6アーム×400戦で我々の最強Grimmsnarlエージェント群に90〜99%で勝っていた。教訓は、**自分に勝つスパーリング相手は壁ではなく候補である。**

## 5. プロセスと、変えるべきこと

このプロジェクトは1人の参加者がAIコーディングエージェントを指揮して進め、全ての判断を共有ステータスファイルで事前登録し(閾値は結果の前に固定、400戦A/Bは「45%以下のみ棄却」規則)、全結果を台帳に追記した。この規律は、もっともらしい改善5件を最終ビルドから締め出した。代償は射程だった。模倣は教師を超えられず(学習データの重心≈1,050、金には1,131が必要)、我々は最終日程をその天井の内側で忠実度を1.6pt上げることに使い、Expert Iterationのループ(蒸留判断5.9万件、停止)を完成させなかった。帯の生態の結果はより良い道を示唆する。1,000+の構成(Dragapult/Kangaskhan/Alakazam偏重)に勝つアーキタイプを選び、その勝者を複製し、そのあと初めて学習済み相手モデル付きの探索に投資する。

## 6. 再現性

コード、エージェント定義、学習メタデータ付きモデルレジストリ、全A/B結果(`results/arena.jsonl`)、試合単位の帯分析(`results/ladder_band_final_20260906.csv`)、実験ログ全文をリンク先リポジトリでMITのもと公開している。`python -m ptcglab.build v6.0o` で提出物そのものを再構築でき、`bc_extract.py → bc_filter_deck.py --key Ogerpon --min-copies 4 → train_bc.py` でモデルを再現できる。コンペ配布データとシミュレータは再配布していない。
