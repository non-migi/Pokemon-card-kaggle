## 3. 我々の失敗を一般則に落とす

コンペ固有の話を捨てて、次回も効く形にしたもの。

### 3.1 測定の分解能を、実験の前に計算する
400戦A/BのCIは±5pt。それ未満の効果は**原理的に判別できない**。
それを知りながら、その帯域の実験を10本以上回した。
→ **狙う効果量が検出限界未満なら、実験そのものを設計し直すか、やらない。**
→ 判定規則は結果を見る前に固定する(「REJECT=45%以下のみ」等)。事後に閾値を動かさない。

### 3.2 「負け試合に頻出する」は「直せば勝てる」ではない
敗戦の92%に出る悪手パターンを見つけて1日かけてルール化したが、
後から**勝ち試合でも同率で起きていた**(集中度0.88倍)と判明。識別力ゼロだった。
→ **必ず勝ち試合の基準率と比較してから着手する。**

### 3.3 天井が既知なら、天井の内側を磨かない
模倣学習の上限は教師集団の平均。学習データの重心はレート約1050で、金は1131。
**締切6日前には「この路線では届かない」と自分で書いていた**のに、
最後の3日を忠実度74%→75.6%(+1.6pt)に使った。
→ **天井を計算し、それが目標に届かないなら、天井を破る仮説に資源を移す。**

### 3.4 スパーリング相手が自分より強ければ、それは壁ではなく提出候補
`bc_ogerpon` は08-10に**壁として**作り、その時点で自陣最強を6アーム×400戦で90〜99%粉砕していた。
この信号を5日放置し、08-15に半ば宝くじとして提出したら即座に自己最高を記録し、最終的にこれが本命になった。
→ **壁の勝率が自陣を上回ったら、その場で提出候補に昇格させる。**

### 3.5 1回の失敗で技術を捨てない
探索は本番A/Bで−88点だった。だが中身は
「相手行動が決定的argmax固定・価値網なし・200手ロールアウト打ち切りなし」という壊れた実装。
正しい結論は「探索は有害」ではなく**「この探索は有害」**。
1位は相手モデルを学習器の入力に持っていた。
→ **棄却するときは、技術ではなく実装を棄却したのだと明示して記録する。**

### 3.6 再発した事故はチェックリストにする
押し出し事故を2回やった。1回目に「提出前に日付順を確認」と書いたのに、文章では再発を防げなかった。
→ **提出スクリプトに検査を埋め込む**(押し出される提出のIDとスコアを表示して確認を求める)。

## 4. 次回の作業順(費用対効果順)

**この順番が結論**。上から順に、下に進むほど金と時間がかかる。

### ① 高速シミュレータを書く(最優先・お金はかからない)
8.7億対局を回すには公式エンジンをPythonから叩くのでは桁が足りない。
観測のシリアライズを避け、C++かベクトル化実装で **1試合1ms級**を目指す。
**ここが最大の参入障壁で、実装工数は数ヶ月。だから最初に着手する。**
副次効果としてローカルA/Bの戦数が2桁増え、3.1の分解能問題も同時に解ける。

### ② デッキアリーナを常時稼働させる(GPU不要)
1位の646デッキ台帳・38アーキタイプ・常時アリーナ・1ペア512戦は**すべてCPUだけ**で回る。
我々は「公式Daily Topの最頻60枚をそのまま使う」で止め、カード1枚も動かさなかった。
→ アーキタイプ内総当たり → 上位同士のクロス対戦 → **4枚未満の変種**で弱点対面を潰す。
→ 対面表が手に入ると、後述のポートフォリオ選択が推測ではなく計算になる。

### ③ 模倣で初期化してから自己対戦RL
公式リプレイのBCは**捨てずに初期化に使う**。ランダム初期化からの探索を丸ごと省ける
(1位のStage 1は全体の40%を占める。ここをBCで代替できる)。
そのあとPPO。相手のデッキ・手札の推定は**手書きの照合ではなくモデルの入力**にする。
ステージは「広いデッキ分布 → 徐々に専門化 → 最後は1デッキ固定 × 凍結世代のラダー」。

### ④ ポートフォリオとして提出枠を使う
最終評価がmaxなら、逆相関のペアを組む。②の対面表があれば、
「どの2本を出せば上振れが最大か」を実データで選べる。
今回それを勘でやって当てたが、次は計算でやる。

## 5. レート帯の生態(今回の独自発見・次回も使える)

最終2,000戦を相手の最終レートと結合したところ、**相手のデッキ構成は帯ごとに違った**。

| 相手の最終レート帯 | 最大勢力の比率 | 我々の勝率(専門型) |
|---|---|---:|
| 700〜800 | Alakazam 40% | 61% |
| 800〜900 | **Grimmsnarl 61%** | **70%** |
| 900〜1000 | Grimmsnarl 29% に低下、Ogerpon/Kangaskhan/Dragapultが台頭 | 37% |
| 1000+ | Dragapult 29% / Kangaskhan 24% | 20% |

専門型エージェントの平衡レート905.8は、**主食であるGrimmsnarlの供給が薄くなる高度**と一致した。
帯構成 × アーキタイプ別勝率を掛けるだけで、帯ごとの当てはめなしに勝率が再現できる
(800〜900帯で予測68.6% / 実測69.8%)。

→ **一般則: 帯Bから上がるには帯B+1の構成に勝たねばならない。
デッキは「今いる帯」ではなく「次の帯」のメタに対して選ぶ。**

再現コード: `scripts/ladder_band_analysis.py`(公開リプレイ × 最終LBの結合)。

## 6. 予算の現実(2026-09時点の試算)

1位の学習量は **3.7 × 10^20 FLOPs = GPT-2(1.5B)の約3.7倍**。

| 条件 | 4090換算 | 費用 |
|---|---:|---:|
| そのまま再現 | 2,918 h | $1,021 |
| BCで初期化してStage 1を省略 | 1,734 h | $607 |
| + 系統を1本に | 1,194 h | $418 |
| + bf16(1位はFP32のまま) | 597 h | $209 |
| + 最終を1デッキ特化1体だけ | **455 h** | **$159** |

**10,000円($67)で買えるのは4090を190時間 = そのまま再現の6.5%**。1位の再現は不可能。
ただし**Kaggleの無料枠が週にGPU 30時間 + TPU 20時間**あり、
TPU v3-8なら上の最小案が約16週で終わる。締切に追われていないなら無料枠で計算量には届く。

**結論: 律速は金ではなく①の実装工数。** ①を持っていない状態では、いくら積んでも届かない。

## 7. やってはいけない(このコンペで反証済み)

- **モデルsoup**(異なる初期化の重み平均): 44.41%。埋め込みの相関がほぼ0で、関数が壊れる
- **エリート限定BC**(高レート帯だけで学習): +0.13pt。質を上げる代わりに量が1/3になり相殺
- **容量拡大**(隠れ層128→256): +0.2pt。忠実度の制約は容量ではない
- **手書きルールの積み増し**: GR003(アタッカー優先)/ GR004(進化ライン温存)は壁A/Bで−4.0pt。
  この評価で唯一CIが分離した差が「有害」側だった
- **温度付きロールアウト**での探索救済: 温度0.5で50.0% / 1.0で34.3%と単調悪化
- **床効果のある壁での±5pt設計**: 全アーム勝率1〜7%では閾値が機能しない。オッズ比か弱い壁を使う
